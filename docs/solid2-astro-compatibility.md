# Solid 2 RC and Astro 7 compatibility

**Research date:** 2026-10-23. This note uses upstream project documentation, source, published package metadata, and issue trackers. No dependency or application file was changed.

## Recommendation

**Do not move this Astro 7 portfolio to Solid 2 RC as a dependency-only change.** Solid 2 requires a coordinated runtime, renderer, compiler, and host-integration upgrade. Astro’s official renderer currently supports Solid 1 only, and the installed TanStack Solid adapters have unresolved Solid 2 compatibility risks. A forced peer override or renderer fork would be unsupported and must not be represented as a supported Astro upgrade.

## What is supported versus unknown

- **Supported today:** Astro 7 with `@astrojs/solid-js@7.1.1` and Solid 1.9.x—the portfolio’s current dependency family.
- **Not supported today:** Solid 2 RC under either `@astrojs/solid-js@7.1.1` or `7.0.0-beta.2`; both peer Solid 1 and are implemented against removed Solid 1 paths.
- **Unknown:** when Astro will ship an official Solid 2 renderer; whether all portfolio Solid libraries will publish compatible releases; and the final Solid 2 RC/stable version set. No such Astro renderer was identified in the cited upstream sources.

## Exit criteria for reconsideration

Revisit only after Astro publishes a renderer that explicitly peers with Solid 2 and uses `@solidjs/vite-plugin`/`@solidjs/web`, and after released (not merely open-PR) fixes exist for the required TanStack adapters. Then migrate packages, JSX ownership, renderer/SSR behavior, and application APIs together, and verify production SSR, hydration, client islands, transitions, forms, and queries as Solid requires. [Solid migration verification guidance](https://v2.solidjs.com/migration/from-solid-1)
